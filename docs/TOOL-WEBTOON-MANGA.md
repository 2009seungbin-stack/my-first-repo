## Job and trust boundary

A creator brings their **own local** long episode artwork or panels, splits or joins them in reading order, makes optional original speed lines, speech balloons and screentone overlays, and downloads a checked ZIP. The page must not fetch or rip hosted comics, provide “free webtoon”/mirror keywords, upload an unpublished manuscript, imply publisher approval, or call a gutter heuristic “AI.” Source files and effects stay in the browser; the only outbound requests are existing static site/service requests that cannot contain the manuscript. Presets are conservative, dated and linked to publisher help. Unknown publisher workflows are **Custom**, never a guessed brand preset.

## Architecture and boundaries

- One indexable task route proposed: `/image/webtoon-manga-toolkit/` with four task tabs and real ko/en/ja copy. A single page avoids thin near-duplicate landing pages. If later search data proves distinct intent, separate slicer and effect pages need substantial distinct examples and an SEO cannibalization review. `src/tool-registry.js`, `src/task/registry.js`, `src/task/strings.js`/locale pattern, `src/seo-depth/`, `tools/build.mjs` and sitemap/lastmod are the shared touch points; the engine lives in new `src/webtoon/*` modules. This is an image-creation tool, not a Studio engine exporter.
- `specs.js`: immutable dated publisher constraints and custom profile. Naver exact width, WEBTOON slice width/height and conservative byte targets, Postype max-side/file; no fixed Kakao/Lezhin dimensions. A UI notice separates hard rules, advisory cut height, user-specified values and unknowns. Report carries the exact source URL/date. Any invalidated official source disables the corresponding branded preset rather than silently falling back to third-party figures.
- `split.js` and `join.js`: pure geometry and scored gutter rows using downsampled row statistics. Store cut boundaries in source pixel coordinates. Detect blank-only or uniform-color false positives, show confidence, and make every suggestion reversible. The output of split followed by join without resize/compression must be pixel-exact in a Pillow oracle; lossy JPEG runs receive a separately scoped comparison.
- `worker.js`: decode one local source at a time, crop and encode one tile at a time, release `ImageBitmap`/canvas resources, stream ZIP entries where possible, cancel cleanly. No network calls or external model. Cap pixels and file count based on measured browser memory, with a visible refusal before unsafe allocation; long images cannot rely on a single giant browser canvas. Settings URL contains profile/version, cut offsets, effect parameters and seed only, never filenames, bytes or user text. Worker progress reports decode, analysis, preview, encode and ZIP.
- `effects.js`: deterministic vector paths for balloons and speed lines; screentone geometry uses PPI/LPI conversion. Keep layered settings model and final raster/export render separate. Sanitize SVG text and reject foreign elements/scripts on independent reparse. Do not market generated effects as proprietary rights; originals can be released CC0, while user artwork remains theirs.
- Task shell: large visible result first, expert panel collapsed, drag/drop + paste + chooser, keyboard access for every cut/tail, focus restored after render, ARIA instructions and live progress, 390 px layout, high contrast and reduced-motion support. Before/after and seam zoom are essential. Download button stays disabled until real checks finish, and a constraint warning is never a fake green approval mark.

## Acceptance and test oracle

1. Commit a small CC0 fixture ledger with origin URL, author, license, date, SHA-256. Use the Kenney strip for deterministic row geometry **and** at least one independently licensed, genuine comic/manga art page from [OpenGameArt CC0 manga-style backgrounds](https://opengameart.org/content/manga-style-background) or another rights-cleared source for hold-out visual cuts. Original hand-drawn dialogue/bubble panels provide a separate known cut oracle. No scraped commercial webtoons and no fixture from an illegal mirror.
2. Pure tests: no skipped/duplicated source rows; each output meets selected verified dimensions and chosen byte targets; Naver height is not hard-capped; WEBTOON 2 MB per image and 20 MB total are conservative targets with source scope labeled; Postype preserves width unless the user opts to resize. Fuzz dark panels, all-white pages, text near gutters, varied alpha, long UTF-8 filenames and image ordering. Failed size-fitting must explain which constraint could not be met.
3. Independent Pillow/ZIP/XML oracle reopens every file, checks decoded dimensions, orientation, pixel coverage, transparency, color mode, output size and total, numbering, PNG alpha and JPEG matte, then reparses SVG with a restricted XML parser. Effects are overlaid on real CC0 artwork and visually inspected at actual 100% and 390 px, including ko/ja lettering. Compare the same CC0 strip and equivalent settings with ToonSlice/ToonSlicer/GAWI; record why gutter/preset differences prevent direct rankings.
4. Browser gate in Chromium and Firefox: chooser, paste and drag/drop; keyboard/manual cut and undo/redo; URL round trip without file data; worker cancel; zero non-GET file-bearing requests; 1440×900 and 390×844 captures inspected; all three languages; reduced motion; no horizontal overflow. Register `tests/webtoon-manga-browser.py` in `tools/regression.py`. Run `npm test`, full regression and `tests/service-browser.py`, plus corpus-hidden Studio checks if shared routing changes. Production `SITE_URL` build, SEO audit, lastmod, hreflang, structured data and depth tests must pass.
5. Performance target to measure, not claim: one genuine 4K-wide page and an 800×30,000 long page, 20-file batch and worst-case effects. Target ≤12 s desktop export and ≤30 s at 390 px with 4× main-thread CPU throttle; no UI stall >100 ms after input selection; document median/p95, peak memory if observable and whether workers are throttled. Physical midrange mobile and printer/RIP color behavior remain **UNVERIFIED** until tested. If targets fail, report exact timings and show a large-job pending/cancel state rather than hiding the miss.
6. SEO is a real creator guide: exact answer, why/when to split, source-checked table, pixel/byte worked example, gutter explanation, safe text/balloon example, tone PPI/LPI example, troubleshooting, alternatives, source dates and limits in ko/en/ja. Do not target piracy-related consumer search terms or imply the tool republishes someone else's comic.

## Risks held for review

### Implementation evidence, 2026-09-29

- The committed `tests/fixtures/webtoon/comic-page.png` is a derived 800×3000 CC0 comic scene. Its source artwork, license and file hashes are recorded in `tests/fixtures/webtoon/SOURCE-LICENSE.md`. It is the real artwork used for the visual checks; the colored geometry fixture is kept separate.
- `tests/webtoon-offline-visual.py` renders the actual effect SVG functions with independent CairoSVG 2.9.1, reparses SVG as XML, reopens raster output through Pillow, composites on the CC0 page, and independently reopens all 9 ZIP members. The offline output ZIP was 4,744,746 bytes. At 800 px and 390 px display widths, panel art and speech remained readable in the inspected composites. The sample applies a panel mask in Pillow to demonstrate editor placement; the product exports transparent overlays and does **not** automatically mask panels. Screentone has visible moiré at the reduced scale. This offline oracle does **not** validate the browser worker's SVG-to-PNG path, which remains pending browser QA.
- `tests/webtoon-header-oracle.py` creates still and animated PNG, JPEG and both WebP encodings using Pillow, then checks the browser predecode header sniffer independently. Six variants pass. Animation is refused before full image decode. The WebP fields follow Google's [RIFF container](https://developers.google.com/speed/webp/docs/riff_container) and [lossless bitstream](https://developers.google.com/speed/webp/docs/webp_lossless_bitstream_specification) documentation.
- The page stays `noindex` until the actual browser effect ZIP, mobile/desktop visual review, performance measurements and full regression pass. Platform acceptance, physical mobile and print behavior remain **UNVERIFIED**.

- Public Kakao/Lezhin upload dimensions are **UNVERIFIED**. Their custom profile must remain visibly custom even if competitor sites publish numbers. Naver 1280 px height and Postype 1600 px width are also unsupported as mandatory rules by the official pages checked here.
- The French WEBTOON Academy's 2 MB-per-image guidance contradicts ToonSlicer's 20 MB-per-image copy. The 2025 contest FAQ has a narrower scope; the UI must make the conservative target and scope explicit. Applying a 20 MB-per-image target by mistake is a release-blocking test.
- Browser decoding of a long page can exceed canvas or memory limits. Build a tiled pipeline and set measured caps; a 4K landscape benchmark alone is insufficient.
- “Gutter-safe” row detection cannot establish narrative safety. A blank panel interior, speech-balloon margin or intentionally silent white frame may score highly; give manual inspection, confidence and undo.
- SVG text and fonts can vary across applications and languages. Reopen PNG and SVG independently; avoid font-embedding promises and unlicensed font redistribution.
- Search volume, platform acceptance, physical-mobile timing, real printer output and paid-competitor parity are **UNVERIFIED**. The coordinator should approve feature scope and the exact profile names before implementation.
