# Pixel Converter T1: measured result and release boundary

Measured 2026-09-28 on `nerulio/tool-t1-pixel`. This is a local quality audit, not a competitor parity or human preference claim. Reproduction scripts are `tests/pixel-converter-{browser,quality,performance}.py`, `tests/pixel-blue-noise-quality.py`, and `tests/pixel-competitor-compare.py`; generated contact sheets and PNGs remain under ignored `test-results/pixel-converter/`.

## Existing cleanup baseline and regression

`docs/pixel-bench/T1-BASELINE.md` resolves the **76 inputs = 69 cases with 1× truth + 7 real generated examples without truth** discrepancy. Exact size/pixel scores use 69, never 76. Original main recovered 81% exact size and 63.2% exact pixels. A rerun after the new photo defaults (`docs/pixel-bench/scores/t1-final.json`) produced the **same aggregate and every group score**, with zero missing outputs. The restoration path did not enter the new photo sampler/quantizer. The 7 real examples stayed at source size; no exact quality score is claimed for them.

## Real CC0 photographs and sampling

The [CC0 landscape](https://commons.wikimedia.org/wiki/File:Flower_landscape.jpg) and [CC0 portrait](https://commons.wikimedia.org/wiki/File:Portrait_(CreativeCommons).jpg) have source/transformation hashes and authors in `tests/fixtures/pixel-converter/LICENSE.md`. On the landscape at 32×32/16 colours, RGB RMSE against a Pillow BOX reference was **6.72** for area-average + Wu, versus 14.27 for median + Wu. On the portrait at 32×21/16 colours, it was **5.25** versus 14.73. These are a *box-reference fidelity proxy*, not artistic scores. All 15 sampler/palette outputs per photograph reopened in Pillow with the requested dimensions and ≤16 colours. Contact sheets were visually inspected: area average keeps the landscape's broad tonal structure but softens details; median gives the portrait's thin arms a firmer silhouette. Both remain selectable. The default is now area-average + Wu because it reduces the measured loss in both distinct scenes, while small feature preservation may favour median.

Wu uses a 32³ Oklab histogram with 3D summed moments and chooses variance-reducing box splits; deterministic and bounded palette tests pass. The 64×64 fixed blue-noise threshold mask was checked at 10/25/50/75/90% fill: its low/high spatial spectral power ratios were **0.024–0.143**, versus **0.806–1.364** for a seeded white-noise mask. It uses one fixed phase across frames. This tests spatial high-pass behaviour, not perceptual preference or every animated sequence. Bayer, Floyd–Steinberg and Atkinson are available independently.

## Same-photo competitor use

`tests/pixel-competitor-compare.py` generated one **1024×768 Lanczos derivative of the CC0 landscape**, loaded that exact PNG into four live browser tools, downloaded their actual output PNGs and independently reopened them with Pillow. The contact sheet was visually inspected. Nerulio, ImagePixel and Pixel Art Village were each set to **32×24, 16 colours, no dither**. ImagePixel used its Original palette; Village used Generate palette from image with 16 colours; Nerulio used area average + Wu. In one reproducible run, RGB RMSE against the same Pillow BOX 32×24 reference was **6.30 Nerulio, 7.97 ImagePixel, 6.76 Pixel Art Village**. A previous Village run gave 6.54 with a different output hash, so its dynamic palette is not fully repeatable in this check. These values cover this photograph/settings only. The contact sheet shows Nerulio with flatter midtone transitions, ImagePixel with relatively clear highlights, and Village with stronger edge contrast; these visual observations do not establish a preference ranking.

The third competitor, image-to-8bit, was exercised on the **same input** with PICO-8 and its maximum 16px block. It exported a 1024×768, 9-colour mosaic, so it **does not meet the matched 32×24/16-colour condition**. Its 18.38 RMSE after BOX normalization is diagnostic only and excluded from the matched comparison. Aseprite and other cleanup competitors were measured in the older restoration audit, a different task; no photo-quality equivalence is inferred from them. No paid-tool output comparison is claimed.

## Formats, privacy and UI

`tests/pixel-converter-browser.py` passed 33 focused checks on real Chromium at port 4701: ko/en/ja UI, URL settings with no file bytes, source retention and one-step undo/redo, 390px layout, and no outside request during conversion. The original CC0 JPEG PNG output reopened in Pillow with byte-identical Studio pixels. A real CC0 GIF and APNG each imported as six composited frames, with one palette across the conversion. Indexed PNG-8 reopened as palette colour type with matching RGBA; `.aseprite` reopened through installed Aseprite CLI and all six rendered frames matched. GIF export reopened in Pillow with matching six frames, centisecond timing, order, and a finite **two-play** loop; it uses GIF's 256-colour/binary-alpha limits and rounds delays below 20ms. A 4× nearest PNG reopened with every RGBA pixel block identical; the UI exposes integer 2–16× factors under an output pixel guard. `tests/pixel-converter-firefox.py` passed 7 checks: the Box/Wu defaults, independently reopened CC0 photo PNG, source retention, and no outside request or page error.

The previous `converter-1440.png` screenshot showed Median because that sprite fixture test deliberately selected Median to verify the control; it did not show the photo default. The photo test now opens Options and checks Box/Wu before saving `photo-1440.png`. A shared import had also booted the task-home file-drop handler inside Studio, so dropping a JPG/GIF could navigate away and lose the active workspace. Commit `77ce930` moved palettes into a pure module; the full Studio browser test then passed 103 checks, including the formerly failing drop.

## Measured performance and limitations

On this Windows desktop and Chromium session (navigator.deviceMemory 32GB), a 3840×2160 landscape derivative with the new default had ten 32×32 preview runs of **0.174–0.252s**, median **0.221s**. Import 0.176s and prepare 0.158s were measured separately. A 390×844 *desktop browser viewport*, using the 2560×1920 photo, ran ten previews in **0.113–0.153s**, median **0.133s**; the same viewport refused 3840×2160 (8.3MP) at the 8MP aggregate-frame guard. This is not a physical phone benchmark. Desktop limit is 48MP aggregate input. Browser heap counters include Studio, so they are not peak process memory. Long GIF/100-frame memory and native mobile performance remain unmeasured.

`/pixel/` is the **one indexable canonical photo-conversion page** in ko/en/ja. It keeps the square quick converter and links to the tested rectangular/animated Pixel Studio path. Its localized intent content covers sampling, palette choices, a measured CC0 example, steps, troubleshooting, alternatives, limits and official format sources. `/image-to-pixel-art/` remains an **existing noindex alias**, canonical to `/pixel/`, excluded from the sitemap; no new doorway page was added. The canonical page has reciprocal hreflang and dated sitemap entries. `/game/fix-ai-pixel-art/` is the separate indexed restoration page and hands files to `?ws=pixel&mode=restore`. “AI restoration” is not used for the deterministic grid/palette heuristics. Public ranking, paid-tool parity, physical-mobile performance, universal 4K latency and broad GIF-player compatibility have no supporting evidence here.
