## Expanded description — ready to paste

Nerulio brings several 2D game-asset preparation tasks into the browser. It can inspect sprite-sheet
grids, work with Aseprite files and frame sequences, edit animation timing and placement, pack
atlases, and produce supported engine export bundles. Pixel-art editing and cleanup, tile-pattern
inspection, and texture/normal-map workflows are also available.

Its focus is asset preparation and conversion between stages of a game-development pipeline.
Choose the workflow that matches the source and check the destination format's limitations before
using the result in a project. It can be used alongside a dedicated pixel editor or atlas packer.

Asset processing happens in the browser. Studio recovery uses local browser storage, and projects
can be downloaded as .nerulio files. Website delivery, external palette/dependency retrieval and
configured online services may still make network requests; local processing does not mean the
site has no network activity. Keep separate copies of original assets and exported projects.

## Differentiators and limitations

Nerulio connects sprite import, timing, placement and engine output with pixel, tile and texture
workspaces in a browser. Files stay in the local asset-processing workflow; downloading project
backups is part of that workflow.

Formats differ in timing and metadata support. Aseprite-to-Godot exports flatten layers; hitbox
data needs engine integration. Rotated TexturePacker input is not a verified Godot conversion.
Normal-map inference can be ambiguous, and missing tiles require art work. Browser memory and
graphics capabilities limit large projects. These are useful boundaries for choosing a tool,
not reasons to claim universal compatibility.
