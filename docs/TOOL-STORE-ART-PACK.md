# T2 Store Art Pack — design gate

Status: **design only; no implementation or parity claim**. Checked 2026-09-28 (Asia/Seoul). Base: `origin/main` `cd1e69a`. Owner review is required before code work.

## User job and boundary

An indie creator has a key-art image, transparent game logo and genuine gameplay captures. They need distinct, upload-ready assets for Steam, itch.io and mobile stores, with each crop and logo placement inspected at its actual display size. The tool must never invent gameplay, a logo, ratings or platform approval. Inputs stay on the device; ZIP and report are generated locally. Store submission remains the creator's job.

The demand reports (`reports/Nerulio 방문자 성장 전략.md`, `reports/Nerulio 방문자 늘리기 아이디어 뱅크.md`) identify Steam capsule/itch guide demand, but their Wayline dimensions were secondary evidence. Current official rules below override them. This is a game publishing workflow, distinct from the existing `marketplace-pack`: `src/platform-presets.js` contains Etsy/Shopify product-photo sizes, and `src/recipes.js` currently produces JPEG fit/cover images and `presets.json`. We will not silently relabel that route or extend Etsy presets as game-store rules. A new canonical intent and task page can reuse the image quality/ZIP primitives where appropriate. `src/task/registry.js` currently points marketplace-pack to generic recipe UI; `src/seo-depth/` plus `tools/build.mjs` supplies static intent content.

## Proposed workflow and architecture

1. New `store-art-pack` canonical task intent with three named inputs: key art, logo PNG (or an explicitly typed title layer), and real screenshot captures. Drag/drop, paste and file picker all use the same local intake. No URL fetching, model calls, analytics carrying file bytes or remote processing.
2. One-screen starter flow: choose platforms → preview all required slots → export. Advanced drawer: per-slot crop/zoom/focal point, pixel-art integer nearest mode, background fill, logo transform, text/locale variants, file format/quality, optional assets. A shared focal point is only an initial suggestion; each slot keeps an override and a visible reset/undo. Never call a heuristic crop “AI”.
3. Pure versioned spec data module with `platform`, `slot`, dimensions, accepted output types, alpha, required/optional/conditional status, warnings, official URL and `sourceCheckedAt`. Keep non-normative safe-area guides separate from hard rules. Steam library hero uses the official 860×380 rectangle; Google center overlay is labelled an advisory illustration. Per-slot filename convention, e.g. `steam/store/header-920x430.png`, `steam/library/hero-3840x1240.png`, `itch/cover-630x500.png`, `google-play/feature-1024x500.png`, `apple/icon-source-1024x1024.png`.
4. Composition state stores source Blob references, normalized focal point, per-slot transforms, logo layer and intentional text. Query string contains only settings and slot transforms, never image data. Undo/redo history stores operations rather than full image snapshots. Before/after and thumbnail-as-seen previews include 120×45 Steam small and a mobile-cropped Google simulation; these previews are advice, not official store renders.
5. Heavy decode/resample/encode and ZIP packaging run in a Web Worker, with bounded tiles, sequential slot output and transfer/release of ImageBitmaps. 3840×1240 hero needs 19 MiB RGBA at one copy; avoid simultaneously retaining every full-resolution output. JPEG/PNG format and alpha are checked after encoding. If a 4K source is insufficient for a slot, report upscaling and offer a deliberate choice; no hidden blur. Pixel art uses exact integer nearest scale where possible, with crop/fill clearly marked; non-integer output fit cannot be described as pixel-exact.
6. Report JSON/HTML within ZIP: each file, dimensions, MIME/alpha/byte size, source, crop/scale, known warnings, manual-review items and spec version/date. Output is `UNVERIFIED` until reopened by an independent parser in test; no “platform approved” badge. Local ZIP preserves user originals only on explicit opt-in.
7. Localization via the task strings pattern in `src/task/strings.js` for ko/en/ja, including natural platform-rule explanations. Static SEO content uses `src/seo-depth/<group>.js`, `src/seo-depth/index.js` and `tools/build.mjs` with answer, principles, worked 4K→slot crop example, output table, upload steps, troubleshooting, alternatives, limitations, official source/version dates. One intent page per distinct user job; no duplicate doorway pages for each dimension.

- **Golden inputs:** choose at least one CC0 high-resolution illustration/key-art-like source, one Kenney/OGA pixel sprite composition, transparent logo made from CC0 glyph/art or our own typography, and real gameplay captures from an open-source/CC0 game. Record author, source URL, license and any derivation in a fixture manifest. Existing `C:\Users\2009s\nerulio-asset-corpus\manifest.json` provides CC0 sprites/tiles (e.g. OGA Sumo Hulk, Kenney UI), but it does not by itself supply a complete high-resolution key art + logo + genuine gameplay screenshot trio. Obtain that separately before declaring real-art QA complete. No non-CC0 fixture committed.
- **Independent exactness:** use Pillow on every exported file and unzip via Python, not the producer code. Assert dimensions, magic/container, decode success, alpha/no-alpha, Google icon ≤1024 KB and ZIP filename uniqueness. For PNG pixel mode, test output against a Pillow nearest-neighbour reference on known integer scales; report SSIM/crop bounds against separately rendered photo references. Inspect edges and small-logo readability manually at 120×45 and in 390px viewport. `checklist.json` values must match actual decoded bytes.
- **Platform rules:** automated assertions for slot metadata and known explicit text layers. Steam hero output cannot include composed title/logo; transparent logo remains separate. Warn on missing logo and screenshot count <5. Human checklist remains for source-raster text, misleading claims, genuine gameplay, artwork suitability and final platform review.
- **Performance budget (target, not measured):** 4096×2160 PNG + transparent logo → all required Steam/itch/Google/Apple outputs in ≤12 s desktop Chromium, ≤30 s representative midrange mobile, peak process memory ≤512 MiB desktop / ≤256 MiB mobile, UI input-to-feedback p95 ≤100 ms. - **UX and gates:** 1440×900 and 390×844 screenshots reviewed; keyboard-only upload/crop/nudge/undo/export; visible focus, screen reader labels/status, contrast, reduced motion; paste and drop parity; URL setting round trip without files. ## Risks and decisions for coordinator

1. **Apple scope:** deliver “1024×1024 icon source” only, with asset-catalog/Icon Composer instruction. Current layered, dark/tinted icon treatment means claiming an upload-ready App Store icon ZIP would mislead.
2. **itch banner:** official page documents banner behaviour but not exact upload dimensions or byte limit. Mark suggested custom size, leave hard validation off until official evidence appears.
3. **Source art vs rule compliance:** OCR and heuristics cannot guarantee that raster art lacks forbidden copy. The user must review; warning text must use the correct mandatory/advisory distinction.
4. **Upscaling:** a single landscape source will not reliably make a persuasive vertical capsule or 3840-wide hero. Slot-specific repositioning, optional alternative art and visible scale factor are core workflow, not an advanced afterthought.
5. **Logo rendering:** a typed title is not automatically a game's actual logotype. If no real logo is available, describe it as a text placeholder and leave a manual-review warning. Steam library hero must remain text-free.
6. **Competitor export evidence:** browser file chooser permission blocked direct file conversion in this design pass. We observed real UI interaction, but no competitor ZIP was decoded. Repeat the export comparison with an allowed input mechanism during implementation; until then parity claims remain unverified.

## Implementation verification (2026-09-28)

- Test corpus is committed under `tests/fixtures/store-art/`; `SOURCES.md` records the original CC0 Scribe image, the 3840×2160 derivative and SHA-256, the original transparent geometric logo and the five **actual Godot 4.6.3 game captures** from Kenney's MIT Starter Kit with CC0 visual assets. Each capture is 1920×1080. The gameplay files are copied unchanged into the ZIP. The source game and test images are not offered as the user's own game artwork.
- `tests/store-art-browser.py` drives the real page in Chromium and Firefox. Pillow reopens each of 17 exported files: 12 generated required slots and five genuine screenshot copies. The independent checks cover dimensions, byte counts, transparent library logo, RGB/no-alpha Google feature graphic, Google Play icon ≤1024 KiB, screenshot SHA-256 identity, and a pixel comparison proving the Steam library hero is the art-only center crop. It also saves desktop, 390px mobile, and 120×45 small-capsule screenshots for human visual review.
- A 3840×2160 PNG generated from the committed CC0 JPEG is the measured worker input. Chromium export-to-download was 1.059 s and Firefox 0.961 s on this Windows workstation; worker checklist records decode 72/95 ms and render+inspect 458/467 ms respectively. A 390px viewport with 4× main-thread CPU throttling exported in 0.803 s, but this does **not** simulate a real midrange mobile GPU or throttle the worker. Mobile 30 s and peak-memory targets remain unverified on physical hardware. Results are one run, not p95. ZIP sizes were 19,059,070 and 17,624,637 bytes. Both desktop outputs met the ≤12 s design target for this one corpus.
- The Wayline competitor exported `scribe-space-key-art-4k-steam-capsules.zip`, 16,903,792 bytes, SHA-256 `6eefbe95953323be5a9f0f56e66785a08fa58d36306ad6ef1b6a228a55e932c3`. Pillow reopened all seven PNGs: 1232×706, 920×430, 462×174, 748×896, 600×900, 3840×1240 and 1920×1080. Its last page-background size differs from Steam's current 1438×810 guidance. Our pack includes other platform slots and a separate logo; direct output-byte and visual quality rankings would compare unlike definitions and are not made.
- Platform acceptance, source-art rights for user uploads, and prohibited text already baked into an image require human review. Apple icon output remains explicitly an Xcode source. Itch 960×300 banner remains an optional user-defined size.
