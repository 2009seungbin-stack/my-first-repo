# SFX Generator — design gate (T6)

Status: **implementation audit below; not verified as a ChipTone/Bfxr superset**. The original design was checked 2026-09-28 against `origin/main` at `cd1e69a`; its earlier future-tense sections remain the target, not completion evidence. Worktree `nerulio/tool-t6-sfx`, assigned port 4706.

## Product job and evidence

The main job is to make a usable game sound in seconds, then deliberately tune and export a reproducible family of variations without leaving the browser. The first screen should show eight presets (coin, jump, laser, explosion, hit, power-up, click, UI), **Generate / Play / Save**, a waveform, and a clearly labelled seed. Advanced controls are collapsed. A sound's settings and seed can be shared by URL without audio bytes. No synthesis input or output is uploaded. This matches the local-first service boundary in `docs/SERVICE-ARCHITECTURE.md`; avoid new processing-network calls. The demand reports call SFX + bitmap fonts a game-jam resource-list opportunity, but their traffic estimates are third-party estimates, not measured demand (`reports/Nerulio 방문자 성장 전략.md`, `reports/Nerulio 방문자 늘리기 아이디어 뱅크.md` in the main checkout).

The output claim must be honest: a user can use and license their *original generated result* commercially and may elect a CC0 dedication; we cannot assert that every imported sample, parameter pack, or third-party contribution belongs to the user. Default presets will be generated from original parameter ranges, not copied audio. Credit is optional. Any CC0 sample library needs provenance and licence records before inclusion.

## Architecture and UX

Use a focused indexable tool landing at `/game/sfx-generator/` (localized ko/en/ja), with the synthesis workspace mounted as a task page or an adjacent ad-free studio surface. `src/task/registry.js` currently routes tools that receive files through `kindOf`; this generator starts without a file, so do **not** fake a file intake. Reuse task chrome/localization/SEO where possible, but add a generator-specific boot path for optional imported `.json`/`.sfs`/sample files. The browser shell should still support picker, drop, and paste for actual imports. Separate static explanatory content from the working surface, following `docs/SEO-CONTENT-MODEL.md`; no ad inside an isolated COOP/COEP workspace. The existing `src/task/strings.js`/`src/messages.js` patterns supply ko/en/ja. Query parameters store schema version + compressed validated settings and seed, never imported PCM or filename. Set strict size and numeric bounds on URL and preset imports. Keep an editable history with undo/redo and explicit “restore original” for mutate.

Pure, versioned modules should live under `src/sfx/`: `schema.js` (validated state and migration), `presets.js` (seeded PRNG and range design), `synth.js` (oscillator/envelope/frequency, per-layer DSP), `effects.js` (filter/phaser/crusher), `mix.js` (layer gain/pan/mute/solo, headroom and optional limiter), `jsfxr-format.js` (foreign format adapter), `wav.js` (PCM encoder), `metrics.js` (independent render diagnostics). A dedicated `sfx-worker.js` receives immutable settings and returns transferable Float32 PCM or encoded bytes; the UI thread only draws a downsampled waveform and controls playback. Playback should use the same rendered buffer as export, avoiding an audible preview/export mismatch. Up to four independent layers, each with envelope and modulation, mix into a 32-bit float master before optional final gain/limiting. No hidden normalisation that changes a reference sound. Abort stale jobs and cap duration, sample count, layers, batch variants and memory.

Signal path per layer: seeded oscillator (square with duty sweep, saw, sine, triangle, white/pink/brown/digital noise) → ADSR plus sustain punch → pitch slide/delta slide, vibrato, arpeggio and repeat → LP/HP with resonance → phaser → bit crush → gain/pan. Anti-aliasing or oversampling must be evaluated against vintage sfxr's deliberately aliased sound; use an explicit **classic/clean** render mode rather than pretending one mode exactly matches both. Expose numerical controls and editable plots with keyboard alternatives, visible focus, reduced-motion support and contrast checks. Default seed changes only on Generate; replay/export with the same schema version and seed must produce identical PCM bytes on the same implementation. Save recipe JSON alongside audio in a batch ZIP.

## Interchange and format contracts

* **jsfxr**: support its documented JSON field set and Base58 short-code (`Params.fromB58`/`toB58`, `b58encode`/`b58decode`) as separate input/output modes; preserve unknown fields in a bounded sidecar only if safe. The Base58 string is not a universal “sfxr parameter string.” Its `oldParams` mode and exact field ordering/quantisation must be inspected in the pinned upstream source before code. A multi-layer Nerulio setting cannot be represented losslessly by a single jsfxr string; export only a compatible single-layer classic preset, with a clear loss report for unsupported waves/effects. Native `.sfs` is a separate binary format; only promise it if tested against the original implementation. Sources: [jsfxr API/UNLICENSE](https://github.com/chr15m/jsfxr), [jsfxr UI/source](https://github.com/chr15m/jsfxr/blob/master/index.html), [original sfxr/MIT](https://drpetter.se/project_sfxr.html).
* **Bfxr**: current Bfxr2 is [MIT](https://github.com/increpare/bfxr2), but `.bfxr`/`.bcol` are separate project formats. Do not expose them as supported until samples from Bfxr2 reopen with settings and sound preserved. ChipTone's site licenses *created sounds* as CC0; this does not license its application code for copying ([ChipTone page](https://sfbgames.itch.io/chiptone)).
* **WAV**: mono by default, stereo when pan/layers require it; 16-bit and 24-bit signed little-endian PCM at 44,100/48,000 Hz. Write RIFF/WAVE `fmt ` and `data` sizes, block align, average bytes/sec and sample rate precisely. 24-bit PCM needs its own interoperability run because Microsoft's basic [`WAVEFORMATEX` reference](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex) explicitly discusses common 8/16-bit cases; consult the [WAVE extensible format](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatextensible) and verify a 24-bit file with ffprobe and independent decoders. Dither at float→PCM quantisation, never clip silently.
* **OGG** means a named codec, not a format by itself. Choose **Ogg Vorbis** for wide game-engine support, with a locally bundled licensed encoder if available; existing Mediabunny Ogg muxing does not itself guarantee Vorbis encoding. Verify codec availability at runtime and disable with a visible UNVERIFIED/unsupported label until end-to-end proof. [Xiph Vorbis specification](https://xiph.org/vorbis/doc/Vorbis_I_spec.html), [Ogg framing](https://xiph.org/vorbis/doc/oggstream.html).
* **MP3**: reuse the repo's vendored Mediabunny MP3 encoder bridge/LAME 3.100 under `assets/vendor/mediabunny-mp3-encoder-1.58.1/`, in a worker, after confirming its MPL-2.0 wrapper and LAME notices in `docs/DEPENDENCIES.md`. A third-party decoder must reopen it. Do not label a file MP3 just because `MediaRecorder` returned a Blob. Include encoder-delay/duration tolerance in checks.
* **ZIP**: stream or bound batch memory; exact selected variants, deterministic names, an index manifest with seed/schema/format/metrics, no server call. Reopen every member with independent tooling.

## Independent acceptance and reference comparison

1. Pin an upstream jsfxr commit and licence record; collect a fixed suite of actual sfxr.me JSON + Base58 examples spanning all four waves, envelopes, filter/phaser and 8/16-bit rates. Capture reference PCM/WAV with the upstream library. Round-trip its strings through our adapter and upstream decoder; compare every supported parameter numerically, with explicit losses/quantisation. This is **format compatibility**.
2. Render the same supported classic parameters through both implementations at the same rate, volume and quantisation. Align samples by cross-correlation, report sample count, peak, RMS, DC offset, clipped-sample count, mean/maximum absolute error, SNR and spectral difference. Test deterministic no-noise cases separately from seeded noise; upstream random noise may prevent bit-exact matching unless its RNG is pinned. No “audio identical” claim without defined tolerance and listening review. This is **signal compatibility**.
3. Generate ground truth ourselves for sine frequency, envelope breakpoints, filter cutoff trend, arpeggio timing, stereo pan, fixed-seed identity and mix headroom. Confirm with FFT/correlation via NumPy/SciPy or librosa and with `ffprobe`/`ffmpeg` or `soundfile` reopening outputs. For lossy Ogg/MP3, compare decoded duration, sample rate, peak, RMS, silence at ends and spectral distance within codec-specific tolerances, not byte equality. Check WAV chunk sizes and exact PCM sample count independently.

Probe WAV/OGG/MP3 in Godot 4.7.2 and in a second independent player/decoder before claiming engine-ready.

## Performance budget and risks

Measure rather than assume: first interactive frame under 2 s on a mid-range desktop, preset preview render under 300 ms for a 2 s/48 kHz single-layer clip, four-layer 10 s export under 2 s desktop and 8 s mid-range mobile, 32-variant batch under 30 s desktop. Record device/browser, wall time, main-thread long tasks, peak memory and output duration; adjust caps only with results. The prompt's 3-minute audio budget is an upper stress case, not the default for tiny SFX. A 3-minute stereo 48 kHz float buffer is about 69 MiB before copies; four simultaneous layer buffers and encoding can exceed mobile memory, so render/mix in bounded chunks and limit concurrent variants.

Top risks: jsfxr Base58 precision and `oldParams` differences; noise RNG and sfxr aliasing prevent naive waveform equality; Bfxr/ChipTone breadth exceeds the listed T6 controls; native `.sfs` differs from jsfxr strings; 24-bit WAV interoperability; Ogg Vorbis encoder availability/licence; MP3 encoder delay; mixer clipping; URL state abuse; mobile canvas/workers; misleading CC0 output claims. **None of the outputs or compatibility claims above is verified for Nerulio yet.** Implementation begins only after coordinator approval of this design gate and the scope of ChipTone/Bfxr parity.
