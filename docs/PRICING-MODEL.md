# 가격 모델

Nerulio는 브라우저 게임 에셋 스튜디오(`/game/studio/`)다. 수익은 **광고 + 구독(Pro)**, Photopea 방식이다: 무료 스튜디오는 데스크톱에서 표시된 광고 칸 하나를 보여 주고, Pro는 그 칸을 없앤다(광고 스크립트 요청 자체가 없음). 모바일·좁은 화면의 스튜디오에는 광고가 없다. 콘텐츠 페이지(홈, /game/ 허브, 랜딩, 가이드)는 본문 광고를 쓴다. 광고 세부는 [ADS.md](ADS.md).

## 요약

| | Nerulio Free | Nerulio Pro (게임 스튜디오 요금제) |
| --- | --- | --- |
| 스튜디오와 도구 | 전부 | 전부 |
| 결과 품질 | 원본 품질 그대로 | 동일 |
| 처리 위치 | 사용자 기기 | 사용자 기기 |
| 워터마크 / 해상도 제한 / 느린 모드 | 없음 | 없음 |
| 스튜디오 엔진 내보내기 | 하루 `FREE_DAILY_STUDIO_EXPORTS`회 (기본 10) | 무제한 |
| 파일 도구 heavy 작업 | 하루 `FREE_DAILY_JOBS`회 (기본 30) | 무제한 |
| 편집·미리보기·실행 취소·자동 저장·`.nerulio` 저장·PNG 한 장 내보내기 | 무제한, 세지 않음 | 무제한 |
| 광고 | 광고 빌드에서 표시 (스튜디오는 1280×700 이상 화면에서 오른쪽 칸 하나) | 없음 — 스크립트 요청 자체가 없고 캔버스가 그 폭을 쓴다 |
| 가입 | 필요 없음 | Google 로그인 |

가격은 코드에 없다. `PRO_PRICE_AMOUNT` / `PRO_PRICE_CURRENCY` / `PRO_PRICE_INTERVAL` 빌드 변수 → `src/service-content.js priceText()` 한 곳에서 `Intl.NumberFormat`으로 모든 언어·페이지·모달(스튜디오 한도 대화상자 포함)에 표시한다. 값이 없으면 "가격은 출시 시 공개"로 표시한다. 실제 청구 금액은 결제사의 가격(`BILLING_PRICE_ID`)이 결정하므로 두 값을 함께 바꾼다. 가격 결정은 운영자 몫이다.

## 철학

- **Free 품질을 낮추지 않는다.** 검색으로 들어온 사용자가 첫 결과에서 실망하면 성장이 멈춘다. 워터마크·저해상도·느린 모드가 없다.
- **처리 비용이 서버에 없다.** 모든 처리가 기기에서 일어나므로 Pro는 "서버 자원 구매"가 아니라 "광고 없음 + 제한 없음"이라는 편의다.
- **가벼운 작업은 세지 않는다.** 자르기 하나, 스프라이트 편집 하나 하러 온 사람은 한도나 계정을 의식할 일이 없다.
- **작업을 인질로 잡지 않는다.** 한도에 걸려도 프로젝트는 자동 저장되고, `.nerulio` 저장·PNG 한 장 내보내기·편집은 계속된다.
- **조용한 UX.** 남은 횟수는 계정 페이지, 한도 대화상자, 그리고 얼마 남지 않았을 때(파일 도구 5회 이하, 스튜디오 3회 이하)의 작은 안내에만 보인다. 도구 화면을 대시보드로 만들지 않는다.

## 스튜디오 내보내기 (`studio` quota class)

### 무엇을 세는가

규칙은 한 줄이다: **엔진용 내보내기 묶음(아틀라스/타일셋/맵 + 엔진 데이터가 든 ZIP) 한 번 = 1회, 크기와 무관.** 나머지는 전부 가볍다.

| 세는 것 (`studio`) | 세지 않는 것 (`none`) |
| --- | --- |
| `studio-pack-export` — Pack & Export: 대상 엔진별 묶음(Godot·Unity·Phaser·Pixi·Defold·LÖVE·Spine·Aseprite 등, 목록의 어떤 형식이든) | 가져오기(이미지·.aseprite·GIF/APNG·아틀라스·폴더), `.nerulio` 열기/저장, 자동 저장·복구 |
| `studio-tile-export` — Tile: 타일셋 ZIP(Godot/Tiled/Unity/LDtk + 샘플 맵 + 충돌) | 모든 편집·실행 취소·미리보기, 격자/레이아웃 감지, 실시간 재패킹, Texture 맵 생성·조명 미리보기 |
| `studio-texture-export` — Texture: 엔진 규약별 맵 세트 ZIP | `.aseprite` 파일 하나 내보내기(사용자 작업의 저장), Texture 노멀맵 PNG 한 장, 채널 패킹 PNG 한 장 |

표는 `src/quota.js`의 `STUDIO_ACTIONS`에 있다. `QUOTA_CLASSES`(INTENTS 전용 표)와 분리되어 있고, `quotaClass()`가 두 표를 함께 본다. 서버도 같은 파일을 쓴다: 모르는 ID는 `UNKNOWN_TOOL`, `none` ID는 `NOT_METERED`. `src/studio`의 모든 `meter('…')` 호출은 `studio` 클래스 ID여야 하고 모든 `studio` ID는 호출 지점이 있어야 한다(`tests/studio-monetization.test.mjs`가 소스를 검사).

### 왜 하루 10회인가 (기본값)

- 경쟁 도구: Photopea는 사용량 제한 없이 광고만, Pixlr는 하루 저장 3회(가장 많이 불평받는 제한, 우회 확장 프로그램이 존재), Canva는 월 AI 사용량, Kapwing은 워터마크+720p, TexturePacker 무료 모드는 결과물에 빨간 스프라이트/워터마크.
- Nerulio는 결과물을 망가뜨리지 않으므로 제한은 "하루에 엔진으로 보내는 횟수"뿐이다. 취미 작업 한 번(시트 가져오기 → 조정 → Godot로 내보내기 → 엔진에서 확인 → 수정 → 다시 내보내기)은 보통 3–8회라 10회 안에 들어온다. 하루 종일 반복하는 전문 작업은 20–50회라 Pro가 필요해진다 — 이것이 전환 지점이다.
- 서버 비용이 없으므로 한도는 순전히 Pro 가치의 지렛대다. 너무 낮으면(Pixlr 3회) 반감을 사고, 너무 높으면 아무도 닿지 않는다. 10에서 시작해 운영 데이터(`/api/v1/admin/stats`의 `freeStudioExportsToday`, `deniedToday`)를 보고 10/15/20/30으로 조정한다.
- 파일 도구의 heavy 작업(기본 30)과 **별도 카운터**다. D1 `daily_usage`의 subject에 `#studio`를 붙인 행으로 센다(마이그레이션 불필요). 이미지 도구를 많이 쓴 날에도 스튜디오 내보내기가 줄지 않고, 반대도 마찬가지다. 로그인 시 두 카운터 모두 이어진다(로그인이 초기화 수단이 되지 않음). 익명 네트워크 버킷(Turnstile 기준)은 두 종류를 합쳐 세며 기본 기준은 `(FREE_DAILY_JOBS + FREE_DAILY_STUDIO_EXPORTS) × 4`.

### 사용자에게 보이는 것

- 남은 횟수가 3회 이하일 때만 각 워크스페이스의 주 내보내기 버튼 바로 아래 작은 한 줄("오늘 남은 무료 스튜디오 내보내기 N회"). 토스트·배지 없음.
- 한도에 걸리면 스튜디오 모양의 대화상자: 오늘 사용한 횟수/한도, 00:00 UTC까지 남은 시간, "잃는 것은 없습니다"(자동 저장·`.nerulio` 저장·PNG 한 장 내보내기 계속 가능), Pro 요약(설정된 가격 포함), 버튼 [닫기] [프로젝트 저장] [Pro 보기(새 탭)]. 현재 탭은 이동하지 않는다.
- 거절된 내보내기는 아무것도 바꾸지 않는다(프로젝트·선택·설정·이전 결과 그대로).

### 계정 서비스가 꺼져 있거나 닿지 않을 때 (로컬 우선)

| 상황 | 스튜디오 내보내기 | 광고 칸 |
| --- | --- | --- |
| `SERVICE_API`가 없는 빌드 (현재 운영) | 제한 없음, API 호출 없음 | 광고 단위가 설정되어 있으면 표시(모두 Free) |
| 서비스 빌드지만 미구성(`SERVICE_NOT_CONFIGURED`) | 제한 없음 | 표시 |
| 서비스에 닿지 않음(네트워크·5xx·차단) | 브라우저당 하루 3회 임시 허용(파일 도구와 별도 칸), 그다음 "잠시 멈춤" 안내. 편집·저장·PNG 한 장은 계속 | **표시 안 함** — 요금제를 모르면 광고를 요청하지 않는다 |
| `/me`가 1.5초 안에 답하지 않음 | 위와 같음(내보낼 때 다시 확인) | 이 페이지에서는 표시 안 함 |
| 서버와 페이지 버전 불일치(`UNKNOWN_TOOL`/`NOT_METERED`) | 허용 | — |

임시 허용이 필요한 이유: API만 막으면(광고 차단 규칙 등) 무제한이 되는 것을 막기 위해서다. 차단해도 잃는 것은 엔진 묶음 내보내기뿐이고 작업은 모두 남는다.

## heavy 분류 (파일 도구, `src/quota.js`)

| heavy | none |
| --- | --- |
| AI 확대(`upscale`), AI 배경 제거(`remove-bg`의 portrait/general 모드), 이미지 압축(`compress`), PDF 압축(`pdf-compress`), 영상 내보내기(`media`, `video-trim`, `video-compress`), GIF(`video-gif`), 오디오(`video-mp3`), 게임 에셋 파이프라인(`refiner`, `texture-map`), 배치 팩(`marketplace-pack`, `print-pack`) | 자르기, 회전/뒤집기, 크기 조절, 변환, HEIC, 도트화/팔레트, 단색 배경 제거, PDF 편집·병합·분할·JPG 변환, 영상 프레임 추출, 스프라이트/아틀라스/타일/여백/파비콘 등 나머지 레시피 |

- 서버는 같은 표를 사용해 모르는 `toolId`(`UNKNOWN_TOOL`)와 `none` 도구(`NOT_METERED`)를 거부한다. 클라이언트가 임의 ID로 행을 만들 수 없다.
- 새 도구를 추가하면 `QUOTA_CLASSES`에 반드시 분류를 넣어야 한다(테스트가 모든 `INTENTS` ID의 분류 존재를 강제). 새 스튜디오 내보내기는 `STUDIO_ACTIONS`에 넣고 호출 지점에서 `await meter('<id>')`.

## 하루의 기준

UTC 날짜. 전 세계 모든 사용자가 같은 순간(00:00 UTC, 한국 09:00, 일본 09:00)에 초기화된다. 시간대 추정·조작 문제가 없다. 사용자에게는 "초기화까지 10시간 42분"처럼 남은 시간만 보여준다. 두 카운터(heavy, studio) 모두 같은 규칙이다.

## 한도 조정

`FREE_DAILY_JOBS`(1–10000, 파일 도구)와 `FREE_DAILY_STUDIO_EXPORTS`(1–10000, 스튜디오)를 바꾸고 재배포한다. 코드 변경은 필요 없다. 잘못된 값은 기본값(30, 10)으로 돌아간다. 가격 페이지의 "하루 N회" 문구는 빌드 시점의 같은 변수로 만들어지므로, Cloudflare Pages에서는 빌드와 런타임에 같은 값이 보이도록 한 곳(Production/Preview 변수)에 설정한다.

## Pro가 실제로 주는 것 (UI에 쓰는 것만)

- 스튜디오 엔진 내보내기 무제한, 파일 도구 heavy 작업 무제한.
- 광고 없음: 스튜디오의 광고 칸과 콘텐츠 페이지 광고 모두. Pro는 Google 광고 스크립트를 요청하지 않는다.
- 같은 로컬 처리, 같은 결과 품질(Free와 동일 — 품질은 요금제로 나누지 않는다).

## 향후 Pro 후보 (문서에만, UI에 쓰지 않음)

아래는 아직 존재하지 않는다. 만들어지기 전까지 가격 페이지·대화상자에 쓰지 않는다.

- 스튜디오 기록(undo) 보존 기간·단계 확대, 자동 저장 스냅샷 개수 확대(현재 프로젝트당 10개).
- 폴더 감시/일괄 재내보내기(여러 프로젝트를 한 번에 엔진으로), 내보내기 프리셋 동기화.
- File System Access "제자리 저장"과 엔진 프로젝트 폴더로 바로 쓰기.
- 클라우드 프로젝트 보관·기기 간 동기화(서버 저장이 생기므로 개인정보 설계 선행 필요).
- 팀: `subscriptions.plan='team'` + 좌석 테이블(migration). Pro 판정 함수에 plan 집합만 추가.
- UI 워크스페이스의 MSDF/SDF 폰트 아틀라스·9-slice 묶음, Pixel 워크스페이스의 일괄 정리 — 들어오면 엔진 묶음이므로 `studio` 클래스로 분류할 후보(한 장짜리 결과는 `none`).
- Cloud Credits: 로컬로 불가능한 작업을 위한 `cloud` quota class와 credit ledger. 현재 서버 처리·파일 업로드는 없다.
- API: `/api/v1`과 분리된 키 기반 네임스페이스. 현재 범위 아님.
