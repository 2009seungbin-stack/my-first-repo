# Bitmap Font Maker 2 — implementation evidence

Checkpoint: 2026-09-28, branch `nerulio/tool-t7-bitmap-font`. This is a working record, not a release approval. The coordinator approved the single UI Lab Font stage and v2 editable project. Real browser and engine gates are pending while other agents use the shared browser resources.

## Implemented and independently checked

- The existing Font stage now supports local BDF and project JSON intake, blank glyph creation, Unicode glyph insertion, pencil, flood fill, filled rectangle, keyboard/pointer editing, 32-step project undo/redo, bearings, advance, ascent/descent and pair kerning. Source PNG bytes remain separate from the editable bitmap project. The existing v1 grid/measured and font-file bake paths remain available.
- One canonical bitmap/metric model writes `font.png`, `font.fnt` (text), `font.xml`, `font-binary.fnt` (AngelCode BMF v3), `font.json` and, for editable projects, `font-project.json`. Within an explicit glyph/contour bound, a module Worker writes `font.ttf` with TrueType `glyf` outlines. OTF is absent from the download UI.
- `python tests/bitmap-font-maker-browser.py --model-only` passes for two CC0 BDFs (`sq.bdf`, `sqb.bdf`): 192/192 glyphs each reopened through Pillow PNG, independent XML and BMF-binary readers, text record counts, v2 JSON and fontTools TTF cmap. Every exported glyph alpha mask equals its editable source bitmap; XML/binary records match every character metric.
- The same independent check reads the existing CC0 Clint Bellanger 128×72 PNG (SHA-256 pinned in the corpus) with Pillow, converts its first 95 8×12 cells into an editable project, and compares every exported atlas alpha mask with the source cell. All 95 match; the source PNG bytes stay unchanged. This is a model-level round trip, with UI import/re-edit still pending browser verification.
- `python tests/font-ttf-quality.py` independently checks the source pixel squares against all 192 TrueType outlines in each CC0 font, horizontal metrics and the sfnt checksum. With default FreeType hinting, 93/95 ASCII glyph rasters match exactly; `i` and `j` differ by one pixel at the detached dot. The UI note tells users to disable hinting and render at the intended integer pixel size.
- Unicode Hangul 11,172 decomposition/round trip and the pinned KS X 1001 2,350-member set pass unit tests. The latter was cross-checked against Unicode Technical Note #60 v2 and Python's EUC-KR repertoire. The UI reports actual current-project coverage, estimated minimum atlas pages and raw RGBA cell bytes; it explicitly says the full 11,172 are not automatically generated.
- The existing local TTF/OTF bake now plans its actual uniform grid before canvas allocation. It caps the input at 1,024 unique glyphs and checks the one-page atlas dimensions and pixel budget for the device; the ko/en/ja UI shows the selected count and cap. This protects the unmeasured 2,350/11,172-character path, rather than claiming either set is exported.
- A per-syllable Hangul component editor now stores user-drawn leading/vowel/trailing masks by orientation and final occupancy in the editable v2 project. It previews overlap count, applies one chosen syllable, and uses the existing undo stack. Pure tests verify `가`, `각`, `힣`, variant selection, mask validation and project persistence. Its browser editing/export and visual quality gate are **pending**; there is no complete template art or bulk-generation claim. For a real visual reference, the [Mulmaru v1.0 OFL release](https://github.com/mushsooni/mulmaru/releases/tag/v1.0) was downloaded only into ignored `test-results`: ZIP SHA-256 `fff80e46f59f9ed72d9b2160ba2cc1a624a149fcf99cc39760769e3eb9685ad5`; fontTools found 11,937 code points including all 11,172 modern Hangul syllables. Its reserved font names and OFL license are retained in the downloaded archive. No Mulmaru art is bundled with Nerulio.
- A 24-syllable Mulmaru reference contact sheet at 16px (`test-results/t7-research/mulmaru/hangul-variants-16px.png`, ignored) was inspected at original resolution. Horizontal/mixed vowels and final clusters visibly need distinct zones; this is a visual reference for future component art, not verification of Nerulio's unshipped composer.
- `python tests/font_hangul_visual.py` built two original hand-drawn 15×15 template variants for `가` and `각`, then used the production composer to render `test-results/t7-research/hangul-component-demo.png` (ignored). Inspection at original resolution found the open and final forms distinguishable and zero mask collisions. This small visual sample checks the selected-syllable mechanism only; 237 positional template slots and human review across syllable classes remain outstanding. The browser gate will reopen the same hand-kit project and compare the exported glyph mask to its two input components.
- Optional `python tests/font-cjk-quality.py test-results/t7-research/mulmaru/unpacked/Mulmaru.ttf` rasterized evenly distributed KS syllables from the external OFL font at 16px into 24×24 cells. The test checks the source cmap and bounds before rendering; this caught a negative one-pixel left bearing in the first attempt, which was corrected with two pixels of pad and `xOffset=-2`. Pixel-outline TTFs with 128/256 glyphs reopened in fontTools and every contour matched the source masks (272,892/540,240 bytes). At 512 glyphs, 48,493 filled pixels exceed the intentional 30,000-contour writer budget, so TTF output is blocked. Pure one-page atlas rendering of all 2,350 KS glyphs yielded 1176×1152 (5.17 MiB raw RGBA) and all 11,172 modern syllables yielded 2544×2544 (24.69 MiB); every cell's alpha mask matched its rasterized source. The compact 2048px/4,194,304-pixel guard accepts the 2,350 atlas and blocks the 11,172 atlas. This verifies a **source-font raster/atlas data path**, not Nerulio's component composer, browser speed, mobile hardware, PNG export or engine loading.
- The external Mulmaru `Mulmaru.ttf` and `Mulmaru.otf` were independently reopened as format references: fontTools reports `\x00\x01\x00\x00` plus `glyf` for the 1,606,948-byte TTF, and `OTTO` plus `CFF ` (without `glyf`) for the 602,988-byte OTF; both have 11,937 cmap entries. Nerulio's writer currently emits only the former outline family. An `.otf` extension on those TTF bytes would not reproduce the inspected OTF structure, so OTF remains absent from the UI/ZIP until a real writer and renderer gate exist.
- Pure module benchmark on this desktop (Node, no browser): a 192-glyph CC0 BDF renders an atlas in 0.68–1.61 ms and writes TTF in 5.98–11.28 ms over three runs; 95 blank 16px glyphs render in 0.64–1.21 ms and write TTF in 1.11–1.98 ms. The BDF atlas was 133×143 and TTF 75,704 bytes. These numbers do not measure UI responsiveness, Worker startup, ZIP creation or a phone.
- `npm test` at `fc0adbd` reported 2,294 passing, one skip, zero failures out of 2,295; the test run built 904 static pages. `node tools/check.mjs` passed. A full final HTTP/browser regression gate remains due after the last product edit.
- The existing indexable `/game/bitmap-font-maker/` ko/en/ja content was corrected for the verified formats and current limits. SEO structure tests 14/14, `npm run build` 904 entries, and production-URL SEO audit 472 indexable pages / 19,189 internal links / zero errors passed. `tools/lastmod-ledger.json` refreshed the six changed landing/app pages and `--check` passed.

## Pending or deliberately hidden

1. **Browser output:** run `python tests/bitmap-font-maker-browser.py http://127.0.0.1:4707` after the shared T2→T6→T5 browser sequence. Confirm ko/en/ja editing, Worker TTF, ZIP bytes, v2 reload, 390/1440 visual layout and no console/network surprises. Screenshots require human inspection.
2. **Real engines:** `python tests/font-engine-fixture.py` already prepares Godot BMFont text and Phaser XML bundles with eight expected glyph images read independently from Pillow's BDF parser. Run `tools/engine-verify/verify.py` in Godot 4.7.2 and Phaser 3.90/4.2.1, compare actual rendered masks, advances and kerning. Unity TextMeshPro still needs a signed-in engine and real import; until then TTF is only fontTools/FreeType verified.
3. **CJK generation:** The UI has an unverified one-syllable component experiment; KS X 1001 2,350 and all 11,172 modern Hangul syllables are **not generated in bulk**. The external-font raster stress check above proves model packing and its compact guard, but does not establish readable component variants, browser throughput, PNG export, engine loading or physical-phone performance. Japanese kana/kanji template output is also not implemented. Keep these out of launch claims.
4. **Format scope:** multi-page BMFont output, OTF outlines and SDF shader import remain unverified/unavailable. The existing font-file bake can produce browser fallback glyphs and antialiasing, as described on the landing page.
5. **Competitor parity:** live BitFontMaker2, FontStruct and SnowB UI were inspected; only Aseprite's sheet round trip was byte-compared. No matched-size exported font from 3–5 competitors was captured. Do not assert visual or feature parity.
6. **Performance:** no physical mobile device is attached or measured. Viewport emulation, if run, will be described only as layout QA. Import guards limit BDF/project files to 32 MiB and manual insertion to 1,024 total glyphs. The desktop atlas cap is 4,096px per side / 16,777,216 pixels total; devices reporting at most 4 GB of device memory or a coarse pointer get a conservative 2,048px / 4,194,304-pixel cap. This is a guard, not a measured phone capacity. The TTF writer separately limits 512 glyphs, 128px line height and 30,000 filled pixel contours. Large project memory and cancellation need further measurement before increasing these bounds.

The CC0 fixtures and provenance are in `tests/fixtures/font-maker/LICENSE.md`. The TTF writer is original source in `src/game/font-ttf.js`; no third-party font writer or font art was vendored. User-supplied font licensing remains the user's responsibility.
