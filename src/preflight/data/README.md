# Data curation

The four catalog files are identities/search aliases/vendor links, **not** affirmative compatibility claims.

OBS has a built-in obs-websocket inclusion record, one precisely bounded real minimum-host failure record (Move 3.2.0 requires OBS 31.1+) and source-backed installation/API observations in its adapter. No blanket compatibility with OBS 33/34 is claimed for StreamFX, Aitum, Source Record or other plugins. The live OBS legacy-path policy was read on 2026-10-05; the Program Files cutoff applies only to the specifically documented plugins/name/bin/64bit structure. The older obs-plugins directory and ProgramData/bin/64bit layout have no fabricated 34 cutoff.

Studio, Blender and Godot ship catalog identities and fictional demo records, with no verified real product compatibility matrix yet. Real inventories therefore return UNKNOWN until a matching verified record is curated. This is a functioning conservative engine, not a claim of exhaustive real-world coverage.

All samples use fictional Demo names and demo-prefixed IDs, sourceType=sample, sample=true, fixed dates, and low confidence. Sample fixtures cannot match real catalog identities. Report exports and saved setups carry this provenance.

Before adding a record: inspect the primary source; express platform, architecture, host range and component range; distinguish minimum requirements from maximum tested support; include lastVerifiedAt and checkedAt; specify requirements/dependencies and evidence-backed actions. Inference and ordinary community posts cannot establish READY. Overlapping records with conflicting statuses yield UNKNOWN.

Dataset modules load only on their own vertical page. Core indexes records by component identity once, supporting a sharded future catalog without changing the algorithm.
