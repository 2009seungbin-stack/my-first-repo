## User job and product boundary

A musician or creator should be able to drop a file, see a **qualified** tempo/key estimate, audition a precisely chosen range, adjust speed and pitch separately, make a loudness-safe cut, and download a ringtone without sending their audio to Nerulio or another processing service. Show the waveform and three primary actions first: **Analyze**, **Edit**, **Export**. Analysis must state when a key is uncertain, when tempo may be half/double, and when audio is too short, silent or non-tonal to decide. An estimate is not an AI claim or a musical ground truth.

The app should avoid a single “magic enhance” button. Default export must keep the chosen range and effects visible and reversible. The working page stays ad-free; explanatory pages can use the site's normal SEO/content rules. Premium/billing is a separate product decision: the editor and all processing remain local, and the tool cannot claim subscription readiness from code alone.

The 123apps page's 40 s M4R copy conflicts with [Apple's current GarageBand iPhone ringtone export limit of 30 s](https://support.apple.com/en-afri/guide/garageband-iphone/chs39284d66/ios). The design uses a **30 s safe preset** and labels it as that Apple workflow's limit, not a universal law for every possible ringtone import path. A valid `.m4r` requires an AAC audio track in an MP4-family container; renaming an MP3 is insufficient. [MDN codec selection](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API/Codec_selection) notes browser AAC encoding gaps, so runtime support and a verified fallback are release gates.

## Proposed implementation and architecture

1. Add an indexable localized `/[locale]/audio-lab/` landing with task-specific explanatory content and an isolated, ad-free editor. Reuse site chrome, privacy copy, font and localization patterns. Confirm route/canonical/hreflang conflicts with the existing audio/video conversion pages before building. Existing `src/media-modern-worker.js` and Mediabunny 1.58.1 provide demux, browser codecs and MP3; reuse only after measuring decode/cancel behavior on the target fixtures. Keep audio bytes out of URLs, localStorage, analytics, `/jobs/authorize` and crash logs.
2. Use a dedicated Worker for demux/analysis/render/export. The UI receives coarse waveform peaks, bounded measurements and downsampled chroma/tempo plots, not a second full PCM copy. `File`/`Blob` input remains local. Decode through the existing Mediabunny/WebCodecs path when supported, with Web Audio `decodeAudioData` only after a tested fallback decision. [WebCodecs AudioDecoder](https://developer.mozilla.org/en-US/docs/Web/API/AudioDecoder) accepts encoded chunks, so demux is a separate step; check `isConfigSupported()` for each codec. Keep cancellation and a generation ID so stale results cannot replace newer imports.
3. Maintain immutable edit state: source identity (name/size/hash only inside the session), decoded metadata, crop start/end, fade lengths/curve, silence thresholds, tempo ratio, pitch semitones, target LUFS/true-peak ceiling, output preset. Undo/redo changes settings; source audio never mutates. Do not persist imported bytes or filenames in share links. Render only the selected section for preview; export uses the same DSP graph at export sample rate. Mark lossy re-encode explicitly.
4. For BPM, downmix with a documented channel rule, calculate onset-strength from positive spectral flux (plus low-band energy to catch kicks), autocorrelate a tempogram, and score candidates over a bounded 50–220 BPM range with beat-consistency evidence. Expose primary, half and double candidates and a confidence based on peak separation, beat regularity and enough beats. No beat or very short material returns “uncertain.” Display 1–2 decimal places only when the estimate supports it.
5. For key, compute windowed STFT, tune to concert pitch by a measured offset if strong, map harmonic energy into twelve chroma classes, suppress obvious percussive frames, and correlate with Krumhansl major/minor profiles. Show tonic, mode, runner-up/relative key and confidence from separation plus stability across windows. A C major triad progression can also fit A minor pitch classes; relative-key ambiguity is expected. Return “no reliable key” for atonal, speech, sparse/percussive or modulating material instead of inventing certainty.
6. Independent speed and pitch controls: prototype WSOLA and a phase-vocoder route on the same fixtures. Resampling alone changes both; use time scaling plus resampling in an explicit order to obtain the requested final duration and semitone frequency ratio. Compare transient smearing, phasing and voice timbre; select a default only after blind listening and quantitative checks. Offer a “simple resample” option if users deliberately want tape-speed pitch change. Bound ratios (e.g. 0.5–2× speed, ±12 semitones) until artifacts are measured. Keep stereo phase coherent.
7. Trim with zoom/pan, numeric start/end, click/keyboard selection and optional zero-crossing or onset snap. Apply configurable fades after trimming, then measured loudness gain and true-peak control. Silence trim must use threshold plus minimum dwell/hysteresis, preserve internal pauses, and preview what is removed. Never make a destructive implicit trim.
8. EBU R128 meter: K-weighted channel energy, 400 ms blocks with 75% overlap, absolute −70 LUFS and relative −10 LU gates for integrated loudness; show momentary (400 ms) and short-term (3 s) where duration permits. Use [EBU Tech 3341](https://tech.ebu.ch/docs/tech/tech3341.pdf), [EBU loudness guidance](https://tech.ebu.ch/loudness) and [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I) as the definitions. True peak needs oversampled measurement; a sample-peak meter is not equivalent. “Normalize to −23 LUFS” is a broadcast preset, not an automatic ideal target for every ringtone. Re-measure the encoded output, because lossy codecs can create intersample overs.
9. Output: WAV (at least 16-bit PCM), MP3 via the site's pinned Mediabunny/LAME bridge, Ogg Vorbis via a separately licensed/verified encoder, and iPhone M4R as AAC-LC in MP4-family structure with 30 s safe preset. [Mediabunny's AAC extension](https://mediabunny.dev/guide/extensions/aac-encoder) offers an FFmpeg AAC WASM fallback where native `AudioEncoder` is absent; it is **not yet vendored or licensed/audited in this repo**. Check wrapper/FFmpeg build licences, source and relink materials before bundling; if unavailable, show M4R as unsupported on that browser rather than emit a mislabeled file. Android MP3/Ogg is a preset for common player compatibility, not a claim of device-specific ringtone installation. Exported file is reopened by an independent decoder and tested on target phones before release wording.

## Reference corpus and acceptance method

The scratch 16 s C-major/120 BPM file is a design probe only. Before implementation, make a committed **CC0 self-generated** fixture set with a script, construction parameters, WAV SHA-256 and machine-readable truth. Include 60/75/90/120/150/180 BPM, half/double-accent variants, swing, sparse beats, silence/short clips and a 120→150 change; C/G/F major and A/E/D minor, relative-key ambiguity, detuning, modulating and atonal/speech controls. Mark truth as production tempo/key, not a claim that listeners must perceive the same pulse or tonality. Separately obtain a small external corpus from [Kenney Music Jingles](https://kenney.nl/assets/music-jingles) (85 files, CC0 on its official asset page), record source URL, author, licence, retrieval date and SHA-256 in the shared asset corpus. Kenney jingles do **not** supply BPM/key ground truth; use them for decode, editing and listening, or manually annotate with two independent musicians before counting them in accuracy.

Use [librosa beat/chroma documentation](https://librosa.org/doc/main/) and [Essentia RhythmExtractor2013](https://essentia.upf.edu/reference/streaming_RhythmExtractor2013.html) plus its [music extractor's Krumhansl/Temperley key profiles](https://essentia.upf.edu/streaming_extractor_music.html) as independent reference implementations, not as truth by fiat. Essentia's RhythmExtractor2013 expects 44.1 kHz; resample inputs for that comparison. Run both baselines on exact fixture bytes and record versions, input resampling, primary/half/double BPM, key and confidence. Proposed gates on the unambiguous self-generated set: at least 95% within ±1 BPM and 90% exact tonic+mode; report half/double accepted accuracy separately. For external music, report confusion matrices and confidence calibration rather than a single accuracy headline. These thresholds are targets, **not measured results**.

For pitch/tempo, compare rendered output with Python/FFmpeg independent measurements: sample-count duration ± one output frame plus codec delay; steady tones within ±10 cents after pitch shifting and pitch-preserving time stretch; onset positions within ±20 ms for moderate ratios; no NaN, DC jump or clipping. Objective spectral/transient scores and blinded AB listening on voices, drums, chords and complex mixes are both required. For cuts, reopen outputs and verify exact selected duration, fades' monotonic energy trend, zero-crossing snap bounds and absence of clicks by boundary delta plus listening. For loudness, use EBU's [published loudness test signals](https://tech.ebu.ch/loudness) and independent FFmpeg `ebur128`/`loudnorm` reports; target integrated reading within ±0.2 LU on compliant signals and true peak within 0.5 dB of an independent oversampled meter. Silence/short clips need explicit “not measurable” handling.

Reopen every output with FFprobe/FFmpeg and a second player/decoder; verify WAV headers/PCM, Ogg codec rather than extension, MP3 bitrate/duration and M4R `mp4a` audio/object type and atom layout. Test ringtone import/play on at least one real iPhone and Android device before calling the presets device-ready; an API-level import alone is insufficient for an audible/install workflow. Keep export byte hashes and settings in a test manifest, never send fixtures to the app server.

## Browser, accessibility, SEO and performance gates

- Chromium, Firefox and Safari where available; desktop 1440 px plus 390 px touch viewport. Picker, drop and OS paste; keyboard-only editing including waveform range and fades; visible focus, screen-reader names/status, reduced motion, no horizontal overflow. ko/en/ja copy and locale-aware numerical formatting. Provide a text alternative for every plotted measurement.
- Assert zero audio-bearing or processing POST requests in a browser network trace. A service/auth request, if product policy later requires it, must carry only operation metadata. Verify ad-free isolated editor under site CSP/COOP/COEP; static localized guide/FAQ/schema/canonical/hreflang/sitemap/lastmod must pass SEO audit without overlapping existing media-conversion intents.
- Measure cold interactive time, 3 min stereo 48 kHz peak Worker/main-thread memory and render wall time on desktop and real mid-range mobile. A 3 min stereo float32 PCM alone is ~69 MiB; multiple full copies are unacceptable. Chunk analysis, bounded waveform peaks, cap decoded duration/file size and abort stale jobs. Proposed interaction budgets: waveform ready <2 s for a 30 s file, range drag under 16 ms frame budget, 3 min analysis under 15 s desktop/45 s mobile and no >100 ms main-thread task. These need actual measurements before release.

## Open decisions for coordinator review

1. Approve the URL/SEO split and the initial format set. M4R is required by the brief but has a browser AAC-encoder gap and a new vendor/licence obligation. Do not expose it as verified until the fallback is audited and tested on a real iPhone.
2. Choose the pitch/tempo DSP path only after prototype A/B and objective comparisons. A single resampling slider cannot meet independent pitch and tempo control.
3. Set corpus and confidence thresholds based on measured results. The one synthetic probe correctly read ~120 BPM/C major in two online analyzers but is insufficient to support accuracy claims.
4. Request human listening and phone-install QA before release. Implementation tests can establish numeric behavior and successful decode, not perceived audio quality.
